# API, встраивание и настройки

## API

| шелл | python (`import kt`) | страница (`window.kt`) | что делает |
|---|---|---|---|
| `kt js <code> [<arg>...]`, `kt js -f <file> [<arg>...]` | `kt.js(code, *args)` | - | выполнить JS на странице, вернуть значение; если код - функция, аргументы уходят в неё строками (из питона - JSON), у другого кода аргументы - ошибка |
| - | - | `kt.gesture(текст, кнопка, fn)` | `fn` там, где браузер требует жест пользователя (выбор файлов, разрешения), результат - из `await`. Если команду только что набрали, Enter и есть жест (браузер считает его ~5 с), `fn` вызывается сразу; иначе страница показывает кнопку |
| - | `kt.events()`, `kt.wait(name)`, `@kt.on(name)` + `kt.run()` | `kt.emit(name, data)` | события со страницы в гостя |
| `kt dl <file>...`, `команда \| kt dl <name>` | `kt.dl(path)`, `kt.dl(data, name)` | - | файл из машины в загрузки браузера (папка -> .tar.gz) |
| `kt up [<dir>]` | `kt.up(dir)` | `kt.write(path, data)` | файлы с устройства в машину; файл, брошенный на страницу мышью, ложится в `/root` (только принесённый снаружи: картинку, которую тащат по самой странице, браузер тоже отдаёт файлом, её страница не берёт) |
| `kt sync`, `kt sync add [<dir>]`, `kt sync rm <dir>` (пакет `sync`) | - | - | копия папки с диска, правки из машины пишутся обратно (Chrome, Edge) |
| `kt copy [<text> \| -s]`, `kt paste` | `kt.copy(s)`, `kt.paste()` | - | буфер обмена; если браузер просит подтвердить, `kt copy` ждёт кнопку «Копировать» внизу (до 20 с) |
| `kt cfg [<key> [<value>]]`, `kt cfg rm [-y] [<key>...]` | `kt.cfg[key]`, `kt.cfg[key] = v`, `kt.cfg.describe()` | `kt.cfg[key]`, `kt.cfg[key] = v`, `kt.cfg(key, v)` | реестр настроек, см. ниже |
| `kt save [<name>]`, `kt load [-y] [<name>]`, `kt snap [rm [-y] <name>...]`, `kt reset [-y] [-b]` | `kt.save(name="")` | `kt.save()` | сохранение машины и снимки в IndexedDB |
| `kt pack [<name> <path>... \| rm [-y] <name>... \| dl <name>]`, `kt unpack <name> [<dir>]` (пакет `pack`) | - | - | архивы в хранилище браузера и обратно, в любую машину |
| `kt info` | `kt.info()` | - | что знает страница: браузер, экран, пояс, бандл, образ, память, сохранение |
| `kt tty [<N> \| new [<cmd>] \| kill <N>]` (пакет `kt-ttyd`) | - | `kt.tty.list()`, `open(cmd, host, keys)`, `go(id)`, `kill(id)`, `input(id, s)`, `font(id, d)`, `attach(id, host, keys)` | виртуальные консоли: список, новая, перейти, закрыть; на клавиатуре Alt+1..9 |
| `kt screen [on \| off \| size]` (пакет `kt-screen`) | - | `kt.screen(on)` | экран поверх терминала: клавиатура и мышь - в машину; `size` - размер для X (нужен `boot.vga`, см. [screen.md](screen.md)) |
| `kt export [<name>]`, `kt import` | - | - | сохранение в файл / из файла |
| `kt share [<name>]` (пакет `kt-share`) | - | `kt.share(rev)`, `kt.source`, `kt.keepSource()` | машина файлом: та же страница со снимком машины, см. [Бандлы](bundles.md#машина-файлом-kt-share). `kt.share` - сохранение с новой ревизией, отдаёт его запись; `kt.source` - исходник страницы без снимка (Blob или null); `kt.keepSource()` - брать его со следующего открытия |
| `kt font [<name>] [<size>]`, `kt theme [<name>]` | - | - | шрифт и тема |
| `kt notify [<text>]` (пакет `notify`, код - `/usr/lib/kt-notify.js`) | `kt.notify(s)` | - | системное уведомление (первый раз спросит разрешение; нужен https или localhost, через file:// браузер их не даёт - только мигает заголовок вкладки) |
| `kt alert [<text>]`, `kt confirm <text>`, `kt prompt <text> [<default>]` (пакет `notify`) | - | - | родные окна браузера: alert, да/нет кодом выхода (0 - да, 1 - нет или отмена), строка на stdout (отмена - код 1). Пока окно открыто, страница и машина стоят |
| `kt pkg [<name>... \| search \| add \| rm \| files]` | - | - | пакеты, см. [packages.md](packages.md) |
| - | - | `kt.exec(cmd)`, `kt.read(path)` | выполнить команду / прочитать файл в госте |
| - | - | `kt.type(text)`, `kt.fit()` | ввод в терминал, подогнать размер |

`kt` без аргументов - "kontrol utility" с версией и список модулей «имя -
описание», аргументы и подробности - в `kt help <модуль>` (нет такого модуля -
ошибка), `kt -v` - версия. Версия - хеш образа, тот же, что `image:` в
`kt info` и в `images/build.json`; лежит в `/etc/os-release` (`VERSION_ID`),
который `build.sh` дописывает отдельным маленьким cpio после хеширования
base + overlay.
HTTP - пакетами `curl`, `wget`, `python-requests` (см. [packages.md](packages.md)); у самого `kt`
скачивания нет, внутри это функция `kt_get` из `/usr/lib/kt.sh`, ей пользуется
`kt pkg`.
Модуль - исполняемый файл `/usr/lib/kt/<имя>` со строкой
`kt_meta "<аргументы>" "описание" "$@"`: описание идёт в список `kt`, аргументы -
в первую строку `kt help <модуль>`. Нотация: `<обязательный>`, `[необязательный]`,
варианты через ` | `, `...` - повтор. Расшифровка - в переменной `KT_HELP` перед
этой строкой, по строке на форму: `rm [-y] <name>...  удалить снимки` - форма и
что она делает, между ними два пробела и больше; колонки выравнивает `kt_meta`.
Строка без двойного пробела - примечание. Строка `KT_CONSOLE=1` перед `kt_meta` -
модуль про вид консолей страницы (`theme`, `font`): в X (задан `DISPLAY`) их не
видно, и `kt` такой модуль в списке не показывает; по имени он работает.

Соглашения у всех модулей (помощники для своих - в `/usr/lib/kt.sh`: `kt_page`,
`kt_js`, `kt_die`, `kt_ask`, `kt_name`, `kt_size`):

- Код выхода: 0 - успех, 1 - ошибка или отмена (закрыли выбор файлов, отменили
  `kt prompt`, `kt paste` при пустом буфере). Страница отвечает на каждый запрос
  со статусом. Ошибка - в stderr: `kt <модуль>: текст`.
- Без аргументов - список (`kt snap`, `kt pack`, `kt sync`, `kt cfg`), удаление -
  подкоманда `rm`. Что теряет данные, спрашивает `[y/N]` (вопрос - в stderr,
  конец ввода - нет): `kt reset`, `kt load`, `kt snap rm`, `kt pack rm`,
  `kt pkg rm`, `kt cfg rm` без ключей; `-y` - без вопроса. Флаги разбирает
  getopts, их можно писать слитно: `kt reset -yb`, `kt pkg rm -cdy`.
- Имена снимков и архивов: латинские буквы, цифры, `.` `_` `-`, до 32 знаков, не
  с `-`; у `kt share` - до 24, к имени добавляется `-xxxxxx`.
- Размеры: до 1 МБ - `N КБ`, дальше `X.Y МБ`.
- Ожидание: пока соединение со страницей живо, `kt` ждёт ответа сколько нужно
  (окно браузера, выбор файлов, долгий `kt save`), Ctrl+C - прервать. Если машину
  восстановили посреди запроса (новый агент гасит `kt-net`), ответ ждётся ещё
  30 с - по соединению или файлом от агента (`KT_WAIT` в `kt.sh`, `kt.WAIT` в
  `kt.py`).
- В питоне ошибка или отмена на странице - исключение `kt.Error`, ошибка в JS -
  его подкласс `kt.JSError`, текст без «Error: ». Бросают его `kt.js`,
  `kt.save()`, `kt.copy()`, `kt.up()`, `kt.paste()` (и при пустом буфере),
  `kt.dl()` и `kt.call(verb, arg)` - команда страницы, как `kt_page` в шелле,
  отдаёт текст ответа. Нет связи с браузером или ответа не дождались -
  `OSError`; `kt.js(..., timeout=N)` - необязательный общий предел в секундах,
  по умолчанию его нет.

Примеры - `kt pkg add examples` (все) или по отдельности: `examples-python`,
`examples-c` (Мандельброт через tcc, картинку показывает `show.py`),
`examples-lua` (жизнь).
Питоновские написаны под MicroPython (`py`), работают и в CPython: `examples-python`
тянет `python-mpy|minipython`, `examples-c` - `micropython|minipython`. У micropython куча 1 МБ, для больших данных -
`micropython -X heapsize=16M` (так делает `run.sh` в C-примере, без micropython он зовёт `python3`):

| файл | что показывает |
|---|---|
| `cam.py [ширина]` | веб-камера в цвете в терминале: полублоки и 256 цветов, кадр берёт `kt.js`; во весь экран, после выхода экран прежний |
| `timer.py [25m\|90s\|5:00] [текст]` | большие цифры и полоса под командой, время в заголовке вкладки, в конце звонок; по умолчанию минута |
| `speak.py текст` | синтез речи браузера, голос под язык текста |
| `qr.py текст` | QR-код в терминале: страница грузит npm-пакет `qrcode` с esm.sh, питон рисует полублоками |
| `weather.py [город]` | погода на неделю с open-meteo: шкала температур, осадки; без города - по геолокации браузера |
| `monitor.py` | окно на странице: процессор с графиком за минуту, память, процессы |
| `paint.py` | рисовалка на странице: цвета, толщина, PNG пишется в `~/drawing.png` |
| `snake.py` | змейка во весь экран, после выхода экран прежний |
| `tkdemo.py` | обычный tkinter: вкладки, форма, рисование на Canvas, список, меню, диалоги; лежит в пакете `python-tkinter` и ставится вместе с ним, а не с `examples-python` |
`import kt` работает и в MicroPython (`py`), и в CPython (`python`): `kt.py` лежит в базовом образе.

```python
import kt
kt.cfg["term.font"] = 16          # числа - числами, on/off - True/False
kt.js("(a, b) => a + b", 2, 40)   # аргументы уходят в JS как JSON
kt.js("kt.cfg()")                 # все настройки dict'ом
kt.js("() => kt.term.cols")       # функция без аргументов тоже вызывается

@kt.on("click")
def click(data):
    print(data)

kt.run()                          # kt.stop() из обработчика - выйти
```

После восстановления сохранения или снимка из бандла страница шлёт событие
`restore` - по нему можно заново нарисовать свой DOM.

Пакету, которому своё на странице нужно всегда, без запущенного слушателя
(кнопка `kt-share`), - исполняемый файл в `/etc/kt/page.d/`: страница
запускает их через `kt.exec`, когда машина готова, - после загрузки и после
каждого восстановления. Скрипт должен уметь запускаться повторно.

События копятся в `/run/kt/events`, только пока их кто-то слушает: первый
`kt.poll()` (он же внутри `events`, `wait` и `run`) ставит отметку
`/run/kt/ev.<pid>`, и без живых отметок агент событие не пишет, а журнал
удаляет. При выходе слушатель снимает отметку, последний забирает и журнал;
отметку убитого слушателя агент снимет на следующем событии.

## Встраивание

Сайт встраивает kotelos в iframe и зовёт API через `postMessage`:

```js
vm.contentWindow.postMessage({ kt: 1, method: "exec", args: ["uname -a"] }, "*");
// ответ: { kt: 1, result: { code, out, err } }   готовность: { kt: "ready" }
```

Методы: `exec`, `read`, `write`, `type`, `emit`, `save`, `cfg`.
Для встраивания удобен маленький бандл, например `python3 bundle.py -o embed.html -n embed --snap`.

## Настройки (`kt cfg`)

| ключ | по умолчанию | |
|---|---|---|
| `save.auto` | on | сохранять машину при сворачивании вкладки |
| `save.timer` | 0 (у бандла с `--save-timer` - его число, в `qt` - 2) | сохранять каждые N минут (0 - нет) |
| `term.font` | 13 (12 на телефоне) | размер шрифта |
| `term.family` | system | шрифт: system или любой с Google Fonts по имени (`kt font Space Mono`); jetbrains, fira, ibm, ubuntu, source, vt323 - короткие имена. Грузятся только при выборе |
| `term.theme` | dark | цвета: dark, light, amber, green, gray (три последних - монохромные, как старые мониторы) |
| `term.render` | dom | чем рисовать терминал: dom (встроенный в xterm, меньше памяти на экранах с высокой плотностью) или canvas (рамки и блоки точно по клеткам) |
| `term.cursor` | block | block, bar, underline |
| `term.blink` | off | мигание курсора; выключено, потому что в фокусе оно всё время занимает процессор (4.5% ядра на DOM-рендере, 1.5% на canvas) |
| `term.scroll` | 5000 | строк в прокрутке |
| `term.mobile` | on на телефоне | интерфейс телефона (на ПК - потестить) |
| `keys.main` | см. ниже | кнопки под терминалом |
| `keys.more` | см. ниже | кнопки под ⋯ |
| `keys.screen` | см. [screen.md](screen.md) | кнопки под экраном (`kt screen on`) |
| `screen.scale` | auto | экран X: точек страницы (CSS) на его точку; auto - на ПК точка в точку экрана, на телефоне - как обычный текст или мельче, если бандл задал `--phone-scale` (в `qt` - 0.75) (`startx` и смена размера, см. [screen.md](screen.md)) |
| `keys.open` | off | показать кнопки под ⋯ |
| `keys.size` | 16 | размер подписей кнопок |
| `boot.mem` | 128 | память при загрузке с ядра, МБ |
| `boot.vga` | off (у бандла с `--vga` - его объём) | экран при загрузке с ядра: видеопамять on (8 МБ), 4, 8 или 16 МБ и `/dev/fb0` |
| `boot.cmd` | | команда в новой машине (после загрузки с ядра или со встроенного снимка) |
| `boot.log` | off | лог загрузки ядра и init-скриптов |
| `boot.worker` | off (у бандла с `--worker` - on) | процессор и устройства v86 в отдельном потоке (Web Worker): терминал, экран и страница не ждут эмуляцию. Со следующего открытия страницы, и для сохранения тоже. См. [internals.md](internals.md) |
| `pkg.repo` | `--repo` бандла (`/repo`) | откуда `kt pkg` берёт пакеты |

`keys.screen`, `screen.scale` и `boot.vga` есть только в сборках с экраном (`--vga`).

`kt font` - список шрифтов, `kt font jetbrains 15` - шрифт и размер сразу,
`kt theme` - темы с образцом, `kt theme amber` - выбрать.

Кнопки задаются как `extra-keys` в Termux, рядами:
`kt cfg keys.main "[['ESC','^C','|','UP','MORE'],['TAB','CTRL','ALT','LEFT','DOWN','RIGHT','KBD']]"`.
Имена: ESC TAB ENTER BKSP SPACE CTRL ALT UP DOWN LEFT RIGHT HOME END PGUP PGDN
DEL INS F1..F12, `^X` - Ctrl+X, MORE - показать `keys.more`, KBD - клавиатура
телефона; всё остальное печатается как есть (можно целую команду).
По умолчанию в первом ряду ESC / - | ~ HOME ↑ END ⋯, во втором TAB CTRL ALT > $
← ↓ → ⌨, под ⋯ - F1..F6 PGUP { } и F7..F12 PGDN [ ], по 9 в ряд, как основные
(Ctrl+буква - через CTRL в основном ряду).
В рядах длиннее 9 кнопок подписи мельче, чтобы не слипались на узком экране.

`kt cfg` без аргументов - ключи, значения и описания: `*` в начале строки -
значение не по умолчанию, умолчание изменённого ключа - в скобках в конце
описания. `kt cfg ключ значение` печатает только новое значение;
`kt cfg term.family X` проверяет, есть ли шрифт на Google Fonts, как `kt font X`.
`kt cfg rm ключ...` - вернуть ключи к умолчанию (свой ключ - удалить), печатает
`- ключ` у снятых. `kt cfg rm` без ключей спрашивает и возвращает к умолчанию
все ключи страницы, свои ключи пакетов (`ai.key`) остаются.

Кроме ключей страницы `kt cfg` хранит свои ключи пакетов вида `имя.ключ` (например `ai.key`):
строки до 64 КБ, пустое значение удаляет ключ. Неизвестный ключ в пространстве
страницы (`term.fnt`) - ошибка, чтобы опечатки не терялись. Страница только
хранит пары ключ-значение и проверяет свои ключи, которые применяет сама;
описания для списка лежат в образе, в `/usr/share/kt/cfg/`: в файле `kt` - ключи
страницы (в списке - только те, что она знает), пакеты кладут свой файл (`ai`)
строками `ключ описание` или `ключ=умолчание описание`. Умолчание ключа пакета
знают `kt cfg` и `kt.cfg` в питоне: незаданный ключ отдаётся с ним, без `=` -
пустой строкой (в списке - `""`), а своё значение, равное умолчанию, не
хранится. Ключа нет ни в хранилище, ни в описаниях - `kt cfg имя.ключ` даёт
пустой вывод и код 1, `kt.cfg[k]` в питоне - `KeyError`, неверное значение -
`ValueError`. На странице (`kt.cfg[k]` в JS) незаданный ключ пакета -
`undefined`; `kt.cfg(k, v)` проверяет как `kt cfg` (шрифт - на Google Fonts) и
отдаёт Promise, `kt.cfg[k] = v` пишет сразу, без проверок, которым нужно время.

Хранятся в localStorage (`kt.cfg`), только изменённые ключи. `boot.mem`,
`boot.vga` и `boot.log` действуют при загрузке с ядра: сохранённая машина и встроенный снимок
восстанавливаются как были (`kt reset` или `kt reset -b`).
В адресе: `?fresh` - не брать сохранение, `?boot` - загрузиться с ядра (если оно
есть в файле). Сохранение при этом остаётся, и автосохранение его не затирает до
явного `kt save` (в терминале об этом строка), вернуться к нему - `kt load`.
`?cmd=...` - команда в новой машине, как `boot.cmd` (при восстановлении
сохранения не выполняется), `?log` - показать лог загрузки один раз,
`?defaults` - ключи страницы по умолчанию, как `kt cfg rm` (например, если
`boot.mem` выставлен слишком большим; свои ключи пакетов и машину не трогает,
вместе с `&fresh` - ещё и загрузиться начисто).

Ctrl+Alt+End два раза за 3 секунды (на телефоне CTRL ALT END кнопками, тоже
дважды) - вернуть ключи страницы к умолчанию (свои ключи пакетов остаются) и
удалить сохранение этого бандла, страница перезагрузится. Это делает сама
страница, без гостя: выручает, когда машина не отвечает и `kt reset` не
работает (например, восстановилось сохранение старой сборки с агентом на TTY).
Снимки не трогает. Одно нажатие ничего не делает и в машину не уходит.
